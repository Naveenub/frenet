# Roadmap
Stack note: built as a Node/TypeScript backend with a plain-JS dashboard, not the Go/Rust + Next.js/React/Tailwind stack in the original spec. Migrating is not planned; see the README "Stack (as built)".
- [x] Phase 1: identity, discovery, encrypted messaging, direct connections, monitoring dashboard
- [x] Phase 2: content-addressed encrypted storage + replication, DHT records, peer-hosted content, DIDs (`did:key`, `did:frenet` rotatable identities, `did:web`), verifiable credentials (VC-JWT, presentations, issuer revocation), account recovery (encrypted backup, Shamir shares). Also done: key rotation with pre-rotation and compromise recovery (`did:frenet`), `did:web`, domain handles (`alice@example.com`, trust on first use). Open: a dashboard view for credentials, identity and handles, `did:web` and handles tested only against an injected fetcher (not a live domain), registry-free human-memorable names. Also done: zero-knowledge membership auth (linkable ring proofs, `src/zkauth.ts`); dashboard view and `frenet zk` CLI included; general ZK statements (SNARKs) not planned
- [ ] Phase 3: decentralized browser (done: gateway, signed updatable names and keyword search, HTTPS browsing through a local tunnelling proxy with optional SOCKS5/Tor upstream, host-based tracker blocking with user rules and list import, per-origin permission manager with dashboard; open: URL-level filtering (needs TLS interception, not planned), a maintained tracker list shipped with updates, testing the proxy against live Tor and real sites; registry-free human-memorable names (domain handles exist), full-text search, dApps open); voice/video (WebRTC signalling + dashboard calls done, TURN server configuration done but untested against a real TURN server, no group calls); communities and group chat (done: owner-managed rosters, signed events; done: sender-side store-and-forward for direct messages, group chat and invitations; done: end-to-end encrypted group chat (per-message key wrapped per member, no forward secrecy); done: chat history sync between members, untested on real networks; open: relaying, queued governance events); node operator tools (done: bans, disconnect, sweep, stats, signed local content reports, content blocklist with purge and 451 (an encrypted file is fully blocked when its key is given, at block time or added later), durable re-announcement of stored blocks, remote administration by operator-listed admin peers (signed, replay-protected, allow-listed, audit-logged; not yet audited); open: shared or gossiped abuse lists, automatic hotline submission and similarity matching (both need an agreement with an outside organisation, see README "Content safety"), announcing resolved name records so a name outlives its publisher's node); governance (done: signed ballots, quorum, delegated voting, discussion period and comments, withdrawal, binding rename and membership proposals enforced by independently re-verified enactments; open: weighted voting, charter or rule-change proposals, history sync so nodes converge, owner-independent invitations)
- [ ] Phase 4: security hardening and release readiness. Done in code: QUIC transport, Sybil resistance (identity proof-of-work, subnet limits, cluster flagging), local node reputation, malicious-node detection with automatic blocking, secure-update verification and signing tools (threshold signatures, expiry, rollback protection), operator-initiated update downloader and installer with backup and rollback, mobile profile for low-resource nodes (Node.js). Also done: single-process scale harness (`npm run test:scale`, `docs/SCALE.md`: 20 to 40 nodes on loopback; it found that content lookup is unreliable in a sparsely joined network until routing tables fill, not fixed), public testnet kit (`Dockerfile` untested, `docs/TESTNET.md`). Open: **independent audits** (must be commissioned from a third party; preparation package in `docs/AUDIT.md`; none performed), scalability beyond one machine and past 40 nodes, the routing-table finding above, native mobile and desktop apps (none exist; only the Node.js mobile profile), a running public testnet (kit only, no hosts or published bootstrap list; `SECURITY.md` contact is a placeholder), trust-root rotation, shared (gossiped) reputation or abuse lists, working DCUtR hole punching, NAT traversal and QUIC on real routers/CGNAT (lab-tested only)
