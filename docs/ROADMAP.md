# Roadmap
Stack note: built as a Node/TypeScript backend with a plain-JS dashboard, not the Go/Rust + Next.js/React/Tailwind stack in the original spec. Migrating is not planned; see the README "Stack (as built)".
- [x] Phase 1: identity, discovery, encrypted messaging, direct connections, monitoring dashboard
- [x] Phase 2: content-addressed encrypted storage + replication, DHT records, peer-hosted content, DIDs (`did:key`), verifiable credentials (VC-JWT, presentations, issuer revocation), account recovery (encrypted backup, Shamir shares). Open: key rotation / compromise recovery (a `did:key` cannot be rotated), distribution of revocations, other DID methods, automatic re-announcement of blocks, a dashboard view for credentials
- [ ] Phase 3: decentralized browser (gateway, signed updatable names and keyword search done; human-memorable global names, full-text search, dApps open); voice/video (WebRTC signalling + dashboard calls done, no TURN/relayed media, no group calls); communities and group chat (done: owner-managed rosters, signed events; open: history sync, relaying, store-and-forward); node operator tools (done: bans, disconnect, sweep, stats; open: remote administration); governance (done: advisory signed ballots; open: enforcement, delegated or weighted voting)
- [ ] Phase 4: security hardening and release readiness. Done in code: QUIC transport, Sybil resistance (identity proof-of-work, subnet limits, cluster flagging), local node reputation, malicious-node detection with automatic blocking, secure-update verification and signing tools (threshold signatures, expiry, rollback protection). Open: **independent audits** (must be commissioned from a third party; preparation package in `docs/AUDIT.md`), scalability tests, cross-platform apps, public testnet, an update downloader/installer, trust-root rotation, shared (gossiped) reputation or abuse lists, QUIC behaviour behind NATs
