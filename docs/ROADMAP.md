# Roadmap
Stack note: built as a Node/TypeScript backend with a plain-JS dashboard, not the Go/Rust + Next.js/React/Tailwind stack in the original spec. Migrating is not planned; see the README "Stack (as built)".
- [x] Phase 1: identity, discovery, encrypted messaging, direct connections, monitoring dashboard
- [x] Phase 2: content-addressed encrypted storage + replication, DHT records, peer-hosted content, DIDs (`did:key`), verifiable credentials (VC-JWT, presentations, issuer revocation), account recovery (encrypted backup, Shamir shares). Done: `did:frenet` rotation, `did:web`, domain-anchored human-readable handles (`alice@example.com`). Handle pinning (TOFU) and did:frenet handle proofs done. Open: cross-node pin sharing / transparency log, distribution of revocations, further DID methods (did:peer), automatic re-announcement of blocks, a dashboard view for credentials. Also done: zero-knowledge membership auth (linkable ring proofs, `src/zkauth.ts`); dashboard view and `frenet zk` CLI included; general ZK statements (SNARKs) not planned
- [ ] Phase 3: decentralized browser (gateway, signed updatable names and keyword search done; domain-anchored handles done; registry-free global names, full-text search, dApps open); voice/video (WebRTC signalling + dashboard calls done, no TURN/relayed media, no group calls); communities and group chat (done: owner-managed rosters, signed events; open: history sync, relaying, store-and-forward); node operator tools (done: bans, disconnect, sweep, stats, signed local content reports, content blocklist with purge and 451 (an encrypted file is fully blocked when its key is given, at block time or added later), durable re-announcement of stored blocks; open: remote administration, shared or gossiped abuse lists, automatic hotline submission and similarity matching (both need an agreement with an outside organisation, see README "Content safety"), announcing resolved name records so a name outlives its publisher's node); governance (done: advisory signed ballots; open: enforcement, delegated or weighted voting)
- [ ] Phase 4: security hardening and release readiness. Done in code: QUIC transport, Sybil resistance (identity proof-of-work, subnet limits, cluster flagging), local node reputation, malicious-node detection with automatic blocking, secure-update verification and signing tools (threshold signatures, expiry, rollback protection). Open: **independent audits** (must be commissioned from a third party; preparation package in `docs/AUDIT.md`), scalability tests, cross-platform apps, public testnet, an update downloader/installer, trust-root rotation, shared (gossiped) reputation or abuse lists, QUIC behaviour behind NATs
- Out of scope (not in the spec's feature list, not planned): HTTPS/general web browsing, tracker blocking and a permission manager (the browser section is only the gateway for FRENET sites), and encrypted group messaging (community chat is signed, protected only by the Noise link to each member)
